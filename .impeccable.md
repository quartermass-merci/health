# Design Context

## Target Audience
Single user — a person following a 12-month science-backed metabolic transformation protocol (310→250 lbs). Opens this app multiple times daily on iPhone via PWA (Safari Add to Home Screen). Not a general fitness app; it's a personal accountability tool for one specific protocol.

## Use Cases
- Morning: rate sleep, see motivational quote, check dashboard status
- During the day: log water, log walking minutes, check feeding window status
- After feeding window closes: confirm stayed in window, do evening check-in
- Anytime: log weight, check carb streak, use 5-minute craving timer
- Weekly: review calendar streak, check weight trend chart

## Brand Personality / Tone
- **Warm, grounded, honest** — not clinical, not gamified, not "wellness influencer"
- **Quietly confident** — the app believes in the protocol and in the user, without cheerleading
- **Utilitarian with soul** — big buttons, clear numbers, fast inputs. But moments of delight (milestone celebrations, insight messages) that feel earned, not decorative
- **Personal** — feels like a tool built for one person, not a product trying to acquire users. No onboarding tours, no upsells, no "share with friends"

## Aesthetic Direction
- Dark theme with warm earth tones (not cool/blue dark mode)
- Accent color: amber/gold (#d4a057) — warm, metabolic, earthy
- Semantic colors muted not neon: soft green for positive, soft red for negative, soft blue for water
- Typography: system fonts (SF Pro on iOS), hierarchy through weight and size, tabular nums for data
- Cards used purposefully for data grouping, not as decoration
- Minimal chrome — no borders unless functional, no shadows unless elevation matters
- Motion: purposeful spring physics on entry, liquid fills on progress bars, but nothing gratuitous

## What Makes It Memorable
The feeding window timer arc that depletes in real-time with color transitions. The weight loss number that counts up on dashboard entry. The confetti burst when you hit a milestone. It feels alive in a way most trackers don't — like the data is breathing.

## Constraints
- PWA: vanilla HTML/CSS/JS, no frameworks, no build step
- Must work offline (service worker)
- All data in localStorage
- iPhone Safari primary target (safe areas, touch targets, -webkit prefixes)
- Chart.js for weight graph (bundled locally)
